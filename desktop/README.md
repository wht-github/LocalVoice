# 本地语音 Windows 客户端

Rust + Slint 原生窗口，软件渲染，不使用 WebView、Node.js 或内置模型。识别由本机子进程提供，可选朗读连接 LocalVoice WSL 服务。

## 启动

在项目根目录用 PowerShell 7 执行 `./desktop.ps1`，或直接运行发布 EXE。Rust 客户端按已保存设置在后台启动 LocalVoice 服务；重复运行 PowerShell 入口不会重复启动已运行的客户端。

普通安装使用 [install.md](../install.md) 中的预编译 Release，程序位于 `.runtime/desktop/local-voice-desktop.exe`。只有修改源码的开发者才需要 Rust MSVC 与 Visual Studio C++ 组件：在 `desktop` 目录执行 `cargo build --release --locked`，然后显式运行 `desktop/target/release/local-voice-desktop.exe`。`desktop.ps1` 始终启动下载的 Release。依赖版本由 Cargo.lock 固定。

## 操作

- 听写：点击“开始说话”或按 **Ctrl+Alt+Space**，然后选择目标输入框。点击“结束说话”或再次按快捷键后，识别完整录音并一次输入。也可以先选择输入框再开始。停顿不会提交文字，录音期间切换输入框不会自动结束录音。
- 连续听写：设置中勾选“连续听写”并保存，下次开始说话后生效。停顿约 700 ms 后识别并写入每次结果完成时的当前激活输入框；切换应用后后续结果跟随新焦点。长时间不停顿时，每份音频最多 25 秒。再次点击结束或按说话快捷键停止，剩余声音仍识别；点取消则丢弃未完成内容。旧设置默认保留手动模式。
- 朗读：选中文字后按 **Ctrl+Alt+R**，再次按下停止。选区读取优先使用 Windows UI Automation，标准 Windows EDIT 控件另有兼容路径；不支持的应用可先复制，再从托盘菜单选择“朗读剪贴板”。
- 取消：停止采集或播放，忽略尚未完成的任务结果；已经输入的文字不回删。已经保留的待提交文字仍可复制。
- 拖动“本地语音”标题移动悬浮窗；点“—”收起到托盘；托盘双击显示，右键菜单可设置或退出。
- 设置可选择 SenseVoice CPU、llama Qwen ASR 0.6B Q8、llama Qwen ASR 1.7B Q8；均在 Windows 原生运行。安装与模型区别见 [桌面模型说明](../docs/qwen-llama-desktop.md)。结束当前听写后更换模型并保存，客户端会重新加载识别服务。
- 设置可修改两个快捷键、麦克风、音色、语速和本机服务地址；播放使用 Windows 当前默认输出设备。
- 取消勾选“启用朗读”并保存，会停止 TTS 模型进程并取消正在播放的朗读，保留听写。重新勾选并保存会加载模型；加载完成前显示服务状态。
- “启动已保存的服务”遵守已保存的朗读开关；“停止全部服务”停止两种模型并取消当前任务。自动启动可单独关闭。识别为客户端子进程：窗口隐藏不影响运行，**退出客户端会同时结束本机识别进程**以释放内存；朗读（WSL）在退出后仍按原方式保留，需要释放时先停止服务。
- 一键管理支持默认 `127.0.0.1:8001/8002` 地址：识别为本机原生 Python 进程（SenseVoice CPU 或 Qwen NVIDIA GPU），朗读按开关启停 LocalVoice WSL 中的 TTS。自定义地址由用户自行管理。没有额外常驻管理服务、管理员弹窗或 WSL 全局配置变更。

开始录音不检查、不绑定输入框。手动模式结束时立即记录 Windows 当前前台窗口、进程和键盘焦点，识别完成后通过 Unicode 键盘输入交付。快捷键未松开时等待松开，期间可以取消。结束后若切换到其他窗口或原生输入控件，结果保留供复制；不会抢回焦点、自动按 Enter 或改写整段内容。已检测到的密码框不自动输入。

手动模式录音期间仅缓冲音频和更新音量条；手动结束后才请求识别。长录音按服务上限在后台拆为不超过 25 秒的请求，优先选静音边界，全部成功后合并成一份结果交给输入框。该内部处理不改变手动开始/结束的行为。未结束的录音缓存有容量上限，达到后明确报错，不悄悄提交部分内容。朗读的资源分块与录音控制独立。

快捷键只登记指定组合，不记录其他按键。普通权限程序无法向更高权限窗口模拟输入；部分自绘编辑器、终端和浏览器控件可能只能使用复制结果。焦点检查与系统输入不是原子操作，极短时间的焦点切换仍存在系统级竞态。

输入不再依赖 UI Automation 判断“可编辑”或比较控件对象身份，因此未暴露标准辅助功能编辑接口的终端和自绘输入框也会尝试正常键盘输入。UIA 仍用于选区读取和密码提示。SendInput 成功代表系统接收了按键，不保证每种应用都处理了文字。

选区读取会沿当前控件的父级查找至前台窗口，并检查该窗口的文档选区，处理聊天正文与输入框不在同一层级的情况。只读取选中范围，不用整页正文代替选区；中间控件不支持选区时会继续查找。未暴露有效选区的应用仍需使用“朗读剪贴板”，不会自动发送复制快捷键。

## 数据与资源

麦克风只在主动开始后采集。手动模式结束前持续缓冲；连续模式在停顿处提交识别，麦克风保持运行。轻量能量检测只用于开头/结尾静音处理；保留录音内的停顿。转换为单声道 PCM WAV 并保留设备采样率，由服务重采样到 16 kHz。

ASR 请求按顺序执行，正在识别、等待识别和等待输入的内容合计最多三份；满队列时停止采集并提示。连续模式中单次识别或输入失败不会自动关闭麦克风；未能输入的文字保留供复制，积累超过 256 KiB 时暂停采集并提示，避免持续占用内存。

TTS 将选区或剪贴板文本作为一次连续朗读（最多 20000 字）。180 字以内的多句、多段文本一起合成；超过时，仅为控制资源将文本打包到每次最多 180 字，优先使用接近上限的自然边界，保持原文和顺序。标点用于正常停顿，界面不显示内部段数。

播放当前音频时提前合成下一份音频，共用一个播放队列，最多缓存当前音频和一份后续音频。不会等待播完才发起下一次合成，也不会将整篇音频全部缓存。若模型生成慢于播放，仍可能暂时缺少后续音频。取消信号由音频线程独立检查，后续 HTTP 请求等待期间也能停止播放；已经开始的服务端推理可能继续到结束。

不保存录音和转写历史；待复制文字仅在当前进程内。设置写入 `.runtime/settings.json`。模型与 Python 环境不由客户端修改（原生识别环境用 `scripts/setup-native-asr.ps1` 安装）。退出客户端会结束本机识别进程；WSL 中的 TTS 需释放时用设置里的停止或根目录 `voice.ps1 stop`。

选区仅在主动朗读时读取。标准 EDIT 兼容路径需要临时读取控件开头到选区末尾的文本，再截取选区；读取量有上限，不保存或发送选区外的内容，不改写剪贴板。

窗口空闲时不持续重绘，无常驻动画。系统辅助功能在独立线程调用；部分异常应用的辅助功能调用仍可能延迟。

隐藏恢复时显式标记整个软件渲染表面重绘，避免 Windows 清空缓冲区后仍只绘制鼠标经过的局部区域。录音结束先提交尾段，再等待 WASAPI 驱动退出。UI Automation 的连接与事务超时分别设为 300 ms；这不是所有辅助功能操作的总耗时保证，多个调用仍可能累计等待。

分辨率、DPI 或窗口尺寸变化后，在框架完成尺寸更新后的首次绘制中重画完整表面；窗口越出新屏幕工作区时移回可见区域。悬浮窗和设置窗口共用此处理，不添加持续重绘定时器。

设置窗口明确激活并显示在前台，麦克风和音色列表在后台加载。Slint 1.17 的 winit 层跨窗口共用鼠标位置，重返相同坐标时可能漏掉移动事件；客户端给悬浮窗和设置窗分别保存坐标并派发点击，避免重复点击失效。真实鼠标三轮打开/关闭验证见 `outputs/desktop/settings-after.json`。

耗时诊断在 `.runtime/timings.jsonl`，约 512 KiB 后清空续写，只记录录音停止、驱动关闭、队列、WAV 编码、HTTP/服务端识别、目标检查和输入等阶段的时间、采样率及音频长度，不保存录音、转写文本或应用名称。用于区分等待发生在客户端、服务端还是输入目标。

2026-09-06 在本机发布版、窗口显示且未录音/播放时测量：程序文件 13.70 MiB，工作集 31.24 MiB，私有提交内存 8.95 MiB。10 秒采样平均占用一个逻辑处理器的 2.19%，折合本机 16 逻辑处理器总量约 0.14%。这是宿主客户端开销，不包含 WSL 模型服务，也不是录音/播放时的峰值。完整数据见 `outputs/desktop/window-check.json`。

2026-09-06 已将默认朗读换为 Melo 中文 / 中英混读音色；CPU 推理，模型显存为 0。试听与资源见 [Melo 部署记录](../docs/melo-and-service-control.md)。此前的 Kokoro 测试数据仅作历史对照。

## 开发验证

维护者发布：提交修改后，在仓库根目录运行 `cargo build --manifest-path desktop/Cargo.toml --release --locked`，再运行 `./.venv/Scripts/python.exe scripts/package-desktop.py`。产物位于 `outputs/release/v<版本>`，包含 EXE、构建提交与第三方许可。将 ZIP 和 `SHA256SUMS` 上传到同名 `v<版本>` GitHub Release，并在下载页面保留 README 中的 Made with Slint 徽章。普通用户不执行这些构建步骤。

`cargo test` 验证手动录音、长音频请求、PCM、文本完整性、朗读预取/缓存上限/取消和快捷键解析。

项目根目录 `./scripts/test-desktop.ps1` 运行发布版的专用输入窗口、真实服务回环和窗口渲染检查，结果位于 `outputs/desktop`。测试不会录音或播放声音。

另外提供显式验证模式：

- `--test-fixture`：创建本程序自己的标准输入框和无 UIA 编辑接口的自绘输入框。
- `--native-check <fixture-pid> <report-path>`：只允许操作该 PID 的专用测试窗口，验证选区读取、中文/emoji 输入、焦点变化拦截和全局快捷键。
- `--service-check <report-path>`：验证真实 TTS→ASR 调用与输入设备枚举；不采集麦克风，不播放声音。
- `--long-tts-check <report-path>`：对超过单次 API 字数限制的中英混排文章自动分段，逐段调用真实 TTS 并验证 WAV，不播放声音。
- `--runtime-check <report-path>`：实际启停专用服务，验证朗读关闭、ASR 进程不变、启动遵守开关和停止全部服务，然后恢复服务；不录音、不播放。
- `--asr-models-check <wav-path> <report-path>`：关闭日常客户端后验证 SenseVoice CPU → Qwen 0.6B → Qwen 1.7B → CPU 的实际切换、转写与停止，不启动朗读、不录音、不输入文字。
- `--snapshot <png-path>`：通过 Slint 自身渲染器导出本程序悬浮窗和设置窗口，然后退出；不抓取其他应用屏幕。
- `--restore-check <directory>`：连续隐藏/恢复三次，用本进程窗口的实际表面比较像素，不调用会补绘的 Slint 截图，也不移动鼠标。`--unpatched` 只用于对照旧显示路径。
- `--display-check <directory>`：只向测试进程自己的两个窗口发送 100%／150%／200% DPI 和显示变化消息，分别模拟表面丢失、窗口越界；对比实际表面与完整重绘结果。不会修改系统分辨率、启动模型、录音或输入文字。`--unpatched` 关闭本轮修复，用于对照。测试 200% 设置窗口时，当前屏幕工作区须能容纳该窗口。
- `--asr-latency-check <24k-mono-wav> <report-path>`：用已知音频测量 24/48 kHz、短/长上传路径，不录音。
- `--focus-check <foreground-pid> <report-path>`：只读检查指定前台窗口的编辑器属性，不读取输入内容。
- `--target-click-check <foreground-pid> <report-path>`、`--selection-click-check <foreground-pid> <expected-text> <report-path>`：点击真实悬浮按钮的诊断模式，禁用录音和播放。脚本 `scripts/check-target-click.ps1` 只点击诊断窗口；可选择已知测试文本做选区验证。

真实麦克风、扬声器和日常应用兼容性需结合实际使用验收，不能用构建或文本回环测试替代。

初版通过专用窗口的选区读取、中文和 emoji 输入、焦点变化拦截、全局快捷键检查，真实 TTS→ASR 回环、设备枚举和两个窗口渲染通过。实际启动保持前台焦点不变，置顶、不激活样式及鼠标激活拦截检查通过，当前显示器下窗口完整可见。资源与窗口检查入口为 `./scripts/check-desktop-window.ps1`，它要求客户端尚未运行，并在检查后保持窗口打开。

长文本更新后共 9 项单元测试通过，覆盖中英混排、引号、换行、小数、缩写、长句边界及超过 20000 字的分段完整性。分段器本身不截断文本；实际朗读入口明确限制为 20000 字。

真实长文本检查：2187 字符的中英混排文章自动拆为 18 段，全部返回有效且非全静音的 24 kHz WAV，合计 272.475 秒音频，串行合成耗时 95.89 秒。原文拼接校验完整一致；未播放音频，不能据此判断听感。报告为 `outputs/desktop/long-tts-check.json`。
