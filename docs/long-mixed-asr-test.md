# 长中英混用音频测试与日常使用配置

2026-09-06，SenseVoiceSmall / FunASR，CPU，4 个计算线程。GPU 未参与。

## 测试材料与方法

使用 [CAiRE/ASCEND](https://huggingface.co/datasets/CAiRE/ASCEND) 的公开真人中英混合语音测试集（CC-BY-SA-4.0），从 hf-mirror.com 下载 test parquet 并校验 SHA256。测试工具使用独立 benchmark Python 环境，依赖来自清华源，没有改动模型环境。

固定随机种子 20260906，从参考文本同时含中文与英文、时长 1–20 秒的样本中选取 137 段，真人语音合计 604.63 秒。样本覆盖 2 位说话者。每段之间加入 0.7 秒静音，组成 **700.53 秒，即 11 分 40.53 秒** 的长音频。

这是一段由真实短录音拼成的长输入，不是一次自然连续录制的 12 分钟讲话。用于验证混读和长输入分段链路；两位说话者、明确静音边界和公开录音环境限制了代表性，不能外推到用户麦克风、噪声、远场或所有口音。

对比三种方式：原始句子边界逐段识别；长音频用能量静音检测切分、自动语言；同样的长音频切分、指定中文。分段器只读取音频，使用 20 ms 帧、RMS <0.003、持续静音 ≥0.45 秒，优先在 8–25 秒间的停顿切分。它是本轮测试工具，不是已经接入产品的 Silero VAD。

评分为规范化后的混合错误率 MER：中文按字、英文按词、数字串按 token，忽略标点和大小写，其他文字系统的字母串仍计入；编辑距离除以参考 token 数。参考 token 共 2138。没有将 OK/okay、HK/H k 等写法视为等价；因此部分错误属于转写形式差异。MER 不能直接改写成“识别准确率”。

## 结果

| 方式 | 请求数 | 总处理耗时 | 请求耗时 P95 | MER |
|---|---:|---:|---:|---:|
| 原始句子边界，自动语言 | 137 | 35.54 秒 | 0.39 秒 | 13.61% |
| 长音频按停顿分段，自动语言 | 63 | 29.91 秒 | 0.61 秒 | 14.22% |
| 长音频按停顿分段，指定中文 | 63 | 30.41 秒 | 0.60 秒 | 14.31% |

长音频自动语言模式 RTF 为 0.0427，约为音频时长的 1/23.4；最慢一段请求 0.90 秒。没有空结果，没有超过 25 秒而被迫从讲话中间截断的分段。错误率说明仍有错词/漏字，不能将无空结果理解为无漏字。

此耗时是文件已经可用后的 HTTP 串行处理时间，不包括实时说话、等待停顿的时间，也不是连续开启麦克风 12 分钟的墙钟压力测试。两个服务保持运行，测试期间没有特意给 TTS 发并发请求。

ASR 在测试前后 PSS 为 1644.64 / 1677.91 MiB，增加约 33 MiB。统计是请求完成时采样，不是完整瞬时峰值；一次测试不能证明长期运行绝无泄漏。

短片段的自动语言判断有一次选为韩语、三次为粤语；长分段自动判断仅出现中英。强制中文没有改善长音频总体 MER，保留 auto 默认，不据此宣称短句指定中文也无效。

短片段中出现的典型错误：英文词组 `computer languages` 被识别成 `can feel language`；`还有 iPhone` 被识别成 `Are you iPhone`。说明目前优先需要比较混读准确率，而不是仅提高计算速度。

## 当前配置与历史对照

- STT 和 TTS：各 4 个计算线程，采用系统默认同等调度权重。
- 按用户说明，两项服务通常不会同时高频使用，因此已取消曾设置的 ASR/TTS 200/20 权重以及 TTS 2 线程限制。
- 两服务组原有 6 个逻辑处理器等效 CPU 额度、6 GiB 内存回收阈值和 8 GiB 硬上限保持不变。
- 全局 `.wslconfig`、其他发行版、隔离与镜像配置均未改变。

历史对照：TTS 降为 2 线程时，生成 6.50 秒中文语音约 2.92 秒，生成 5.38 秒英文语音约 2.27 秒。此处保留测量记录，当前已恢复 4 线程。此次配置调整没有替换音色或改变音质。

TTS 后续保持轻量路线：可试听同为 82M 的 [Kokoro v1.1-zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)，其官方提供更多中文音色，但官方也说明它不是全面优于 v1.0。本次未下载或切换该模型，也没有增加更大的 TTS 常驻服务。

当前 HTTP 接口仍限制每段 30 秒，测试页面仍限制短录音。长输入是在测试客户端切分后逐段发送，尚未把长文件上传或持续麦克风 VAD 接入产品。未来桌面端沿用分段方式即可控制内存，但须另测真实讲话和切换焦点。
