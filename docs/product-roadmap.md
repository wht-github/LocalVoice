# LocalVoice 产品规划

更新日期：2026-10-19。当前发布版本为 **v0.4.2**，下一阶段列为 **v0.5.0 候选需求**。v0.4.2 根据日常输入等待偏长的反馈，加入录音时后台预热和可选连续轻整理；模型、提示词与完整输出预算保持不变。v0.4.1 补齐独立便携发布：下载 ZIP 后双击启动，首次准备基础 CPU 模型，整理模型与单套 Qwen 按需下载，无需源码仓库或开发环境。v0.4.0 已接通原生录音、人声检测、识别、Agentic 轻整理与笔记自动输入，运行与安装不依赖 Python。全文对照、重新整理、可关闭的笔记调试窗口和整理模型空闲释放均已实现。功能交付与识别、整理质量分开验收，以下质量目标仍需实际使用验证。安装方式见 [安装说明](../install.md)，当前结构与实测见 [原生运行说明](native-runtime.md)。

现有实现采用 Qwen ASR 的可选术语上下文，SenseVoice 保留不带词表的识别；AgenticASR-Refiner Q4_K_M 为日常和笔记共用的本地整理模型，使用作者原生协议，CPU 4 线程、4096 上下文、0 GPU 层。旧 Qwen3-0.6B／1.7B 与 Qwen3.5-4B 方案保留为评测记录，不再是应用整理配置。Agentic 不注入专名表，不针对某个数字或词做替换。用户提供的 AGV／blueprint／UE／transition 句是文本开发用例，没有对应真人音频，不能据此声称术语识别准确率提升。

当前交付边界：新配置默认原样转写，已有设置不覆盖，日常轻整理可选；日常默认手动结束后统一整理，也可选择停顿后按段整理输入，笔记始终手动结束。原文始终保留，对照窗口默认关闭。两者目前使用同一保守整理能力；预热和连续交付不代表模型质量提升。前轮 Agentic 工作集约 1.20 GiB、短句约 1 秒、755 字长段约 9–10 秒；存在数字改口遗漏和长段不通顺。最新有限验证没有找到值得采用的提示增强，已停止追加提示实验，优先完成试用闭环并根据真实使用反馈决定下一步。

LocalVoice 的目标是成为一个用起来舒服的本地语音输入工具：听懂中英混合的技术表达，把口述整理为可以直接使用的文字，并支持把一段想法变成笔记。接下来先让实际使用中的失败可以恢复、问题可以定位，再按真实收益改进术语识别和正文整理。模型、推理引擎和部署方式围绕这些体验选择。

判断产品是否进步，首先看每段话需要手动修改多少，以及整理后是否忠实原意，再看等待时间和资源占用。不能用文字更通顺掩盖术语听错，也不能用模型跑分快替代实际输入体验。

用户补充的核心约束：日常使用不应依赖手工维护纠错词表。常见计算机术语、英文缩写、自然中文口音中的英文名称，以及此前没有登记的新词，首先由 ASR 本身识别。空词表的真实口述表现是首要门槛；词表仅为项目专名提供可选补充，不作为上手步骤，也不以不断要求用户加词弥补基础模型不足。若未登记术语持续出错，优先更换或改进识别模型。Whisper large-v3 / large-v3-turbo 纳入无词表对照候选，详见 [选型补充](asr-engine-selection.md#无需维护词表的术语识别与-whisper)。

## 辅助整理必须轻量

最新约束是：文字整理只是一项辅助能力，不能为了它常驻一个较大的模型或明显挤占 UE 的资源。先确定资源预算，再在预算内选质量合格的模型；若不合格，就缩小自动整理范围，不能反过来不断增大模型来维持原方案。

建议首轮预算为：整理模型权重尽量低于 1 GB，优先纯 CPU、额外模型显存为 0，活动工作集尽量低于 1.5 GiB；短句新增等待目标约 1–2 秒。以上是本轮提出的产品目标，不是用户给出的精确硬上限，也不是已经达到的测量值。文件大小、工作集、私有提交、CPU 时间和显存分别记录，不能只报参数量或下载大小。

v0.4.0 的日常轻整理和笔记共用 Agentic 原生协议，目前没有另一个笔记专用模型或格式化规则。日常输入看实际减少多少修改；笔记还要检查时间、条件、顺序和已完成／待办状态。后续只有实测收益足够时才拆分策略，不为模式名称增加一套模型。较强模型若仍需保留，只作为主动选择的增强能力，不成为启动或日常输入的依赖。

早期实测九种配置、238 个输出后，没有找到可直接接替默认整理的小模型。350M–1.2B 的 CPU 方案能将模型工作集降至约 0.68–1.50 GiB，但存在改义或没有实际整理收益；4B 对照工作集约 3.38 GiB，整卡显存增量约 1.91 GiB，755 字符笔记耗时约 34 秒且仍漏细节。去除提示示例的单因素消融未解决问题。这是后续采用专用 Agentic 模型之前的比较记录，不是当前仍需执行的模型扩展计划。当前已实现模型资源释放，未另行增加规则清理分支。逐项证据见 [资源与质量对比](dictation-evaluation.md#辅助整理的资源与质量对比)。

当前实现按需加载与 60 秒空闲卸载：启动识别服务不会加载文字模型；日常或笔记开始录音时后台准备已安装的整理模型，让加载与说话重叠，录音期间保持可用。录音结束后恢复空闲计时，每次整理完成再重置；健康状态查询不延长驻留。空闲释放后再次使用自动加载，退出服务关闭所属进程；磁盘缓存权重保留。状态区区分已安装待用、加载中、整理中和就绪。CPU 路线仍会与 UE 争用处理器和内存带宽，零 GPU 层不能替代实际共用体验验收。

最新的两个专用模型已经完成本机测试：14 个独立短文本及 1 条 755 字长笔记，各跑作者原生和追加正文要求两组，共 60 次生成。AgenticASR-Refiner 的 Q4 文件 688 MB，模型工作集约 1.20 GiB，短句中位约 0.93／1.17 秒，长段约 9–10 秒；保留了本组中英术语和大多数细节，但一条短句删掉最终速度值，长段改口也未整理通顺。MyVoiceTyping 的 Q4 文件 986 MB，工作集约 1.89 GiB，长段约 14 秒，两组几乎全是复制原文。追加正文要求没有解决核心问题。

随后按用户要求只尝试一个通用正文提示，用提前固定的 8 条新中英短口述、2 段长笔记和单列的旧数字回归验证；没有写死用例规则。新增提示未改善短句或长段，旧数字遗漏仍在，因此不采用该提示，不继续堆提示。用户明确优先开始实际使用，本地试用版采用轻量 Agentic 原生协议，同时保留原样默认、失败回退和全文对照；这是一项可试用能力，不是质量已达标的声明。MyVoice 暂不用于正文整理。识别层继续沿用 SenseVoice／Qwen3-ASR，摘要和强制待办不属于当前正文整理目标。证据见 [有限调优与试用交付](dictation-evaluation.md#一次有限调优与本地试用交付)。

## 当前使用方式

输出模式与识别模型分开。常用面板提供输出模式，模型与硬件选项留在设置中。一次录音开始时固定模式，处理中不切换。

| 输出模式 | 使用流程 | 交付方式 |
| --- | --- | --- |
| 原样转写 | 开始说话，结束后识别 | 保留现有自动输入行为，便于核对识别和保留口吻 |
| 日常输入 | 默认手动结束后统一整理；可选停顿分段整理 | 每段完整结果一次输入，不重写已输入的前段；质量验收通过后再考虑设为推荐默认模式 |
| 笔记 | 连贯口述一段想法，手动结束后识别并统一整理 | 完整正文一次输入，最近结果保留原文与正文供核对 |

手动日常输入与笔记共用结束录音时的目标检查；等待中切换窗口或控件时，结果留在应用内供复制。连续模式开始前选好输入框，开始时绑定目标，切换目标后停止采集并保留后续结果。两种模式都不自动替换已输入文字。

已有用户升级后保留选定的输出模式和录音偏好，新配置默认原样转写。v0.4.2 将连续偏好扩展到日常输入，因此原先已开启的用户在日常模式也会停顿分段交付；需要手动结束后统一整理时，应关闭此项。首次使用整理模式前可在设置中准备本地整理模型；缺少模型时明确提示并保留完整转写，下载只在主动准备时发生。

连续输入支持原样转写与日常轻整理。日常停顿至少 1200 ms 后整段识别、整理并输入，沿用同一 Agentic 模型、协议和输出预算；长时间不停顿约 25 秒提交一段。等待时间分开看录音分段、队列、识别、模型加载和正文生成，不为提速缩短输出或改成摘要。积压达到 45 秒时停止继续录音，完成已接受内容。时间分段不能理解跨段改口，已有正文不回写；需要统一整理的长表达应关闭连续模式。笔记始终手动结束，也不改变保存的连续偏好。

## 中英混合术语识别

目标是正确保留英文词形、技术名称、缩写、代码标识符，以及它们周围的中文含义。评测素材应来自真实使用场景，例如算子、模型部署、代码讨论和技术笔记；attention、KV cache、FlashAttention 等仅为示例，不要求使用者事先登记这些常见术语。

当前保留一份可选本地专名表，包含规范写法、可选别名和简短说明，仅在设置中编辑，不占据结果交付的主要操作。空表也必须能够正常识别和整理。别名只收录用户确认的说法，不把某次误识别自动保存为永久替换规则，也不自动读取其他应用的文本来学习。

当前实现与后续验证边界：

- Qwen 识别前已支持有限的可选术语上下文，SenseVoice 不使用词表。专名上下文的质量收益需要与同段音频的空词表输出分开比较。
- Agentic 当前只接收本次原始转写，不注入专名表、不做识别后词表替换。保留英文技术名称、不擅自翻译属于质量目标，不能因为写入整理协议就视为已经达标。

评测必须分别记录原始 ASR 的术语正确率和最终输出的术语正确率。只有整理阶段改对了词，不能据此宣称识别模型本身改善。加入词表后，还要检查未在词表中的内容，防止把普通词误改为技术名词。

从已有 Qwen3-ASR 1.7B 开始验证主力体验，以 0.6B 和当前 SenseVoice 作基线。只有真实口述暴露持续的术语识别问题时，再按同段音频增加 Whisper 等候选；不把新一轮模型比较作为开始使用的前置条件。先比较空词表的原始 ASR，再单独评估术语上下文。不能用给定词表后的成绩代替对未登记名词的泛化能力；不因已接入某个框架而锁定模型，也不因模型更大就默认胜出。

## 日常输入的口语整理

轻整理只做能减少编辑工作的改动：删除无意义的语气词和重复，处理明确的口头修正，补标点和合理断句。允许调整局部语序以便阅读，保留说话人的表达强度与技术含义。

必须保留数字、单位、版本号、专名、否定关系、条件和不确定性。“可能”“还没测”“初步认为”属于内容；“不是 A，是 B”不能整理为 A；“先用 A，不，还是 B”可整理为最终选择 B，前提是修正关系明确。强调性重复和不明确的反复不能一概删除。

例如口述：

> 嗯，我觉得这个 attention 算子，主要是那个 memory bandwidth 的问题。不是计算量不够，是访存。然后可以先试一下 fusion，不过这个还得测。

期望的日常输入效果示例（不是本版模型实测输出）：

> 我觉得这个 attention 算子的主要问题在 memory bandwidth，也就是访存，而不是计算量不足。可以先尝试 fusion，不过还需要测试。

原始转写和整理结果一起保留在最近结果视图中，均可复制。整理超时或失败时，日常输入与笔记都回退为完整原转写并提示；交付前仍执行同一套焦点和取消检查。原样恢复指取回原文，不承诺自动撤销其他应用中的输入。

最近结果首版只保留一份完整任务的原文和处理结果，退出后清空。未能交付的文字沿用现有待复制机制，不因新结果到达而被覆盖；不建立历史列表或数据库。

整理模型只处理本次原始转写。口述中的指令是待整理的内容，不能改变整理规则、触发外部操作或让模型回答口述中的问题。

## 笔记模式

笔记模式服务于一分钟左右的想法、技术排查过程和待办口述，接下来重点验证实际使用中的 30 秒至 3 分钟录音。停顿保留在同一次录音中；用户结束后，所有 ASR 分块完成并合并，再对完整文字整理一次。

期望输出是忠实、连贯的完整正文，内容较长时合理分段。v0.4.0 与日常输入共用 Agentic 原生协议，尚未实现独立的笔记排版策略，也不强制套用标题、结论、行动项等模板。保留关键细节，不把笔记做成压缩摘要；任务负责人、日期和结论必须来自口述。

上面口述的期望正文示例（不是本版模型实测输出）：

> 我初步认为，这个 attention 算子的主要问题是 memory bandwidth，也就是访存，而不是计算量不足。可以先尝试 fusion，不过这一判断和方案效果还需要测试。

笔记完成后自动输入结束录音时的目标。设置的“口语整理与笔记”提供“笔记完成后显示对照窗口（调试）”，默认关闭；开启后仍先交付文字，再显示窗口，不抢输入焦点。开关只控制额外窗口，手动最近结果入口始终保留。结果视图展示完整笔记与原始转写，支持复制和重新整理；重试复用本次转写，无需重新录音，也不再次向外部应用输入。

长内容超过整理上下文或输出预算时，明确保留完整转写，不静默截断或只展示前半篇。首版不引入分层摘要来绕过限制；先验证选定模型能处理上述录音范围。

## v0.5.0 候选需求与实施顺序

先让用户持续使用当前便携版本，并把使用中遇到的问题变成可定位、可恢复的任务。以下是候选顺序，不代表五项必须一次完成，也不要求先开展一轮大规模模型评测。

| 优先级 | 需求与现状依据 | 验收条件 |
| --- | --- | --- |
| P0 · 1 | **识别失败后重试本次录音。** 当前失败会提示重说，现有“重新整理”仅复用文字；长笔记因此容易丢掉一次完整口述。 | 仅在内存保留最近一段录音，可在失败后重试识别；有明确容量上限，取消或退出清空。重试先显示结果供复制，不重复输入；不建立录音历史或数据库。 |
| P0 · 2 | **最小的问题反馈入口。** 当前能对照全文，也有不含正文的阶段耗时，但缺少把本次问题与运行信息放在一起的入口。 | 用户主动选择“记录这次问题”后，导出原文、正文、模式、模型、阶段耗时及问题说明；音频必须另行明确选择。默认不保存、不上传，不自动生成纠错词表。先支持少量真实问题的定位，无需通用评测平台。 |
| P1 · 3 | **让麦克风与人声状态可区分。** 当前音量条来自 RMS，Silero 的人声判定未在界面显示。 | 设置中可做简短麦克风检查，区分“收到声音”和“检测到人声”；无语音结束时提示原因。用实际轻声、键盘声、风扇环境检查首尾漏字；固定参数仍有明确问题时才考虑简单灵敏度选项。 |
| P1 · 4 | **长笔记的完整性与衔接。** 当前已整段交付，但数字改口、长段连贯性和 ASR 切分边界仍待真实使用验证。 | 用使用中产生的 30 秒至 3 分钟录音核对数字、术语、否定、条件和关键意思；先修可定位的边界漏字、重复、漏段问题。整理不新增事实、不变成摘要，超限仍回退全文；不继续堆提示或写死用例规则。 |
| P2 · 5 | **与 UE 共用时的资源与等待体验。** Agentic 已空闲卸载，ASR 当前持续驻留至停止；短样例回环不能说明共用体验。 | 记录短句、长笔记及 UE 同时运行时的结束到输入耗时和 RAM/VRAM，确认整理模型按时释放。只有实际争用影响体验时才增加“快速响应／空闲释放识别模型”选择，并明确冷启动代价。 |

建议首个实现批次是“本次录音可重试”与问题反馈入口的最小版本。随后按真实错误分布选择下一项：原始转写已错就检查收音和 ASR，原文正确而整理改错就检查整理。空词表术语错误持续存在时再比较候选模型，不能靠后处理掩盖识别缺陷。整理质量未达到原意保护要求前，保持原样转写为新配置默认值。

## 验收与消融实验

实际试用先从少量主动保留的问题开始，覆盖中英混说、陌生术语、数字、否定、自我纠正、轻声和背景噪声。需要更换模型或作质量声明时，再建立开发与独立验收两组；早期规划的 40 条短句加 5 段笔记开发集、20 条短句加 5 段笔记验收集可作后续参考规模，不作为开始使用或修复具体问题的前置条件。录音和参考文本由用户主动提供或明确录制到本地评测目录，日常使用仍不自动留存。

以下百分比和时间为早期提出的质量目标，不是 v0.4.0 已达到的指标。开展质量比较时，先确定基线并冻结验收口径；未达到时说明差距，不能通过删掉困难样例来达标，也不为达到指标持续堆提示。

| 体验 | 初始验收目标 |
| --- | --- |
| 术语准确 | 空词表下常见技术词与未预登记词的规范词形正确率目标 ≥95%；可选专名表单列增益，同时检查中文和英文的一般识别错误 |
| 轻整理有效 | 人工修到可直接使用且忠实原意时，必要修订的字符总量较原始转写减少 ≥30%；原本无需修改的句子单独检查，不能被整理坏 |
| 原意保留 | 验收集中因整理新增的数字、否定、条件、确定性、关键术语等严重语义错误为 0 |
| 笔记可用 | 人工标注的关键要点全部保留，无新增事实；冻结验收的 5 段中至少 4 段无需重写主体结构即可保存 |
| 输入可靠 | 焦点切换、取消、重复快捷键、超时、失败重试的固定场景通过；无错误目标输入、重复输入或取消后继续交付 |
| 等待可接受 | 以本机 7840H / RTX 4050 Laptop 6 GB 为首轮目标环境；热态 1–15 秒日常口述，从手动结束到最终文字可交付，目标 p50 ≤2 秒、p95 ≤4 秒；长笔记按时长分组，首轮测量后冻结预算 |

ASR 使用忠实口述的参考文本；轻整理和笔记按可用性及语义保留评判，不能混用逐字转写与整理目标。术语按规范写法与预先定义的等价形式计分，不能在看到结果后随意扩充答案。

轻整理由评审者分别将原始转写、整理结果修到可直接使用，记录实际必要的字符插入、删除和替换量，避免为贴合单一范文而惩罚合理改写。只在基线确有修订需求的冻结样本上计算下降率，已无需修订的样本单独检查不退化；评审时隐藏模型名称并交错比较顺序。笔记参考以关键要点为主，允许不同措辞。小样本通过只说明这些场景通过，不代表所有口述都不会出错。

每个性能样例重复运行，分开记录冷启动与热态，短句与长段分别汇总；不把用户等待松开快捷键或目标失效后的等待混入模型耗时。记录模型、量化、词表版本、整理配置、音频时长、队列、ASR、整理及总耗时；日常诊断日志仍不记录口述正文。

针对已经出现的问题选择必要的消融，每次只改变一个因素，不要求每次发版跑完所有组合：

1. 固定切分、采样率和格式化设置，对比当前三个 ASR 候选，再按错误类型决定是否增加候选模型。
2. 固定 ASR，比较空词表与可选识别上下文，确认收益与误改；Agentic 当前没有词表分支，不为凑对照新增实现。
3. 固定原始转写，比较原文与 Agentic 输出；同时看编辑量、语义错误和额外等待。模型若没有明显收益，就保持原样入口，不增加更重处理层。
4. 长笔记先核对完整转写与整理正文；只有将来实现独立笔记策略时，才比较它与日常轻整理的差异，检查是否更便于保存且不漏细节。

若后续更换 VAD，另做固定 ASR 和静音窗口的对照，再独立调整窗口。不要同时换引擎、切分、词表和整理方式后归因于某一项。

## 技术选择的边界

| 技术事项 | 本版安排 | 重新选择的条件 |
| --- | --- | --- |
| ASR 模型 | Qwen3-ASR 0.6B / 1.7B 与 SenseVoice INT8 均可选择；各识别模型都可接原样、日常或笔记模式 | 真实术语错误、长句稳定性或等待时间成为主要问题时，做同音频空词表对照 |
| 整理模型 | Agentic Q4 CPU 原生协议，按需加载、60 秒空闲释放；日常与笔记自动输入，最近结果保留全文对照 | 根据实际使用中的错误和收益决定是否更换模型，不继续堆提示或默认增大模型 |
| 推理运行时 | Rust 直接管理 Qwen 与 Agentic 的独立 llama.cpp 进程，私有回环端口；固定版本下载 | 所需能力不受支持，或实测无法满足资源与延迟预算 |
| SenseVoice 原生执行 | 已完成：官方 sherpa-onnx Rust API，INT8 CPU 模型，不再通过 FunASR/Python | CPU 识别质量、速度或稳定性暴露明确问题时再调整 |
| VAD | 已完成：Silero 629 KiB 模型、CPU 单线程、无前置 RMS 门限；原样与日常可选停顿提交，笔记手动结束 | 真实轻声漏检、噪声误检或首尾截字暴露问题时，固定 ASR 做对照后调整 |
| 去 Python 与按需安装 | 已完成：当前启动、录音、识别、整理、安装与打包不依赖 Python；旧研究文件不参与主流程 | 根据干净环境安装与更新中的实际阻碍简化入口，不重新引入 Python 依赖 |

ASR 与文字整理使用不同模型，复用运行时不代表复用同一个已加载模型，也不代表第二实例零成本。已有短样例回环验证切换与释放；下一阶段结合真实使用观察共存时的峰值显存、冷启动和持续工作。只有资源确实不足时再比较更小候选或按阶段加载，并把切换等待计入体验。CPU 整理仍需单独验收，不承诺与 GPU 推理同等速度。

沿用现有模块：[录音](../desktop/src/audio.rs)与 [VAD](../desktop/src/vad.rs)处理收音和首尾，[模型管理](../desktop/src/runtime.rs)与 [SenseVoice](../desktop/src/sensevoice.rs)执行识别，[识别与整理流程](../desktop/src/service.rs)保留原文并串联 [Agentic](../desktop/src/text.rs)。[任务控制](../desktop/src/main.rs)统一处理模式、取消和交付，[界面](../desktop/src/ui.rs)与 [Slint 布局](../desktop/ui/app.slint)提供设置和最近结果。[llama.cpp 进程管理](../desktop/src/llama.rs)负责所属进程生命周期，识别与整理保持独立模型状态。

保持有界队列，不以扩大队列掩盖整理变慢。模型工作在后台线程或所属原生进程中执行，输入继续通过已有目标检查。SenseVoice 与 Silero 当前在宿主内调用原生库；只有实际稳定性问题证明需要时才增加进程隔离，不把 `catch_unwind` 当作原生库崩溃隔离。

当前量化权重见 [AgenticASR-Refiner 社区 GGUF 固定版本](https://huggingface.co/MigoXV/AgenticASR-Refiner-GGUF/blob/2680cd2ec627e7ae61d9288b5d6f314cb6af2e6a/AgenticASR-Refiner-Q4_K_M.gguf)，来源、体积和 SHA-256 固定在下载器；运行时参数见 [llama.cpp b10809 服务说明](https://github.com/ggml-org/llama.cpp/blob/b10809/tools/server/README.md)。框架研究保留在 [识别引擎选型](asr-engine-selection.md)，开发优先级以本规划为准。

## 后续范围

本版不扩展到会议说话人分离、实时字幕、跨应用逐字回写、知识库、自动事实补充、自动学习纠错或完整笔记管理。笔记先交付给使用者已有的工具。

下一阶段按上面的五项候选需求取舍。当前先用录音时预热与可选连续轻整理回应已经出现的等待问题；更多笔记格式、自动学习纠错和新模型接入暂不展开。每次扩展都要能解释它减少了哪一种修改、失败或等待，收益不明显的组件应删减。
