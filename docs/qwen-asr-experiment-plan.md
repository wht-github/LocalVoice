# Qwen3-ASR 1.7B：量化与解码实验协议

本协议在查看候选模型的真人录音结果前建立。目标是找到当前 RTX 4050 6 GB 上值得使用的配置，并保留可复现、可解释的失败结果。暂不修改上游算子。

## 1. 固定数据和度量

使用 ASCEND 官方 test split（真人自然中英会话、人工转写），固定仓库修订和文件 SHA-256。按实际音频时长 2–15 秒过滤，再按 ID 的固定哈希排序，每种语言选前 10 条作为 pilot、随后 10 条作为 holdout，共 60 条。样本清单纳入 Git，音频留在忽略的 `.runtime/` 中。

这两个子集都来自原始 test，并非说话人独立的新划分。这里只做小样本探索，不能代替全量基准或个人麦克风录音。holdout 在 pilot 选定候选后才运行，不根据识别结果重新选录音。

报告中文 CER、英文 WER、中英混合 MER。MER 将汉字视为一个 token，连续英文字母/数字视为一个词；采用 NFKC、小写、忽略标点，保留填充词，不进行同音替换或语义改写。每组以总编辑距离除以总参考 token 数计算，不平均句子百分比。短句、空输出和截断必须保留并标记。

## 2. 固定模型与运行条件

固定 llama.cpp 提交和同一份 Qwen3-ASR 1.7B BF16 主模型。Q8_0、Q6_K、Q4_K_M 均在本机从 BF16 直接量化，记录命令、文件大小、哈希及时间；不对 Q8 再量化，也不使用评测文本做校准。音频编码器始终使用同一 BF16 mmproj。

统一 greedy、最多生成 512 token、context=1024、batch/ubatch=256、parallel=1、threads=4、Flash Attention=on、FP16 KV。关闭请求间提示缓存、RAM cache 与自动 fit。首先尝试全部 GPU 层；若 BF16 无法容纳，记录失败，并区分质量参考和相同 GPU 放置条件下的速度对照，不能静默回退。

## 3. 最小实验矩阵

| 阶段 | 对照 | 唯一有意改变的因素 |
| --- | --- | --- |
| 量化 pilot | BF16 / Q8_0 / Q6_K / Q4_K_M | 主模型权重量化类型 |
| 解码 pilot | Q8_0 原配置 / Flash Attention off | 注意力实现 |
| 解码 pilot | Q8_0 原配置 / CUDA Graph off | 仅设置上游支持的 GGML_CUDA_DISABLE_GRAPHS=1 |
| 后续诊断（仅在证据需要时） | Q8_0 参考 / 单项配置 | 先写假设再增加一行，禁止同时堆叠改动 |
| holdout | BF16、Q8_0 与 pilot 选出的一个候选 | 验证候选在未用于选择的录音上是否仍成立 |

每条录音质量评测一次；性能子集固定为 pilot 每种语言按时长排序的最短和最长录音，各预热一次、计时三次。质量用例也记录耗时，但不与预热性能数据混合。保存客户端总时间、服务端 prompt/decode 时间、生成 token 数、显存和逐条转写。token 数变化时优先同时看解码 ms/token，不能只看总耗时。

Q8_0 是部署参照。pilot 候选优先要求混合 token 总错误率相对 Q8 增加不超过 1 个百分点，同时降低显存或稳定延迟。这个阈值仅用于本轮筛选，样本量不支持统计等价结论。若候选退化，就保留 Q8；不得为了得到正面结论临时改阈值。

## 4. 版本与交付

先提交已有成果；数据/评测工具、量化记录、结果总结按阶段提交。保持脚本职责清楚，不引入通用实验平台。逐条指标与摘要 JSON 纳入 Git，模型、录音和冗长服务器日志不纳入 Git。任何推荐都附上误差变化、显存、耗时范围与实验局限。

数据来源：[ASCEND](https://huggingface.co/datasets/CAiRE/ASCEND)，[论文](https://arxiv.org/abs/2112.06223)，许可 CC-BY-SA-4.0。模型来源与编译环境见已有 `qwen-llama-baseline.md` 和 `llama-native-windows.md`。
